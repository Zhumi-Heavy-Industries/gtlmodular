# 测试

有两种测试：

| 测试 | 命令 | 测什么 | 要多久 |
|---|---|---|---|
| 单元测试 | `gradlew.bat build` 时自动跑 | 批次状态机和存档编码，不启动游戏 | 几十秒 |
| GameTest | `runFullGameTest` / `runNacGameTest` | 启动一个真实的测试服，自动搭机器、放料、供电，检查结果 | 每套 5～7 分钟 |

改了 NAC、样板总成、能量或配方相关的代码，两套 GameTest 都要跑，FAIL 必须是 0。

## 跑 GameTest

先准备测试依赖（见 [依赖.md](依赖.md) 的「测试依赖」）。然后一条一条跑（每套测试服占 6 GB 内存，不要同时跑）：

```
gradlew.bat runFullGameTest --offline
gradlew.bat runNacGameTest --offline
```

- 第一次跑要联网下载 Forge 和映射，去掉 `--offline`。
- 测试服的目录是 `run-test/`（完整版）和 `run-test-nac/`（独立版），每次启动会清掉旧日志和旧报告。不要往这两个目录的 `mods/` 里放任何 jar。
- Minecraft 的 EULA 已经同意过，任务会自动写 `eula=true`。
- `gradlew.bat clean build` 写成一条会失败，分成 `gradlew.bat clean` 和 `gradlew.bat build` 两条执行。

## 看结果

命令最后一行打印 `PASS=… XFAIL=… XPASS=… FAIL=…`：

| 结果 | 意思 | 怎么办 |
|---|---|---|
| PASS | 通过 | — |
| FAIL | 失败，命令返回失败 | 必须修好 |
| XFAIL | 已登记的已知问题，这次按预期出现了 | 不算失败 |
| XPASS | 已登记的已知问题，这次没出现 | 可能已经修好了：确认后去掉它的已知问题登记，让它变成必过用例 |

只有已经登记过的问题才能算 XFAIL。新出现的失败不许登记成已知问题来"过测试"。

详细结果在 `build/reports/gameTest/`：

- `<产品>.json`：每个用例的结果；
- `<产品>-logs.json`：日志巡检。测试服日志里出现本模组的 WARN/ERROR，或任何模组的 Mixin 应用失败，都会让测试失败。预期内的 WARN 写在 `gradle/gametest-log-audit.gradle` 的白名单里，每条都要写原因，ERROR 不能放进白名单；
- `<产品>-recipe-conflicts.json`：配方冲突扫描；
- `<产品>-resources.json`：翻译、模型、贴图检查。

测试服的完整日志在 `run-test/logs/latest.log` 和 `run-test-nac/logs/latest.log`。

0.3.139 发版时：完整版 PASS 41、XFAIL 5；独立版 PASS 28、XFAIL 5；FAIL 都是 0。

## 测了什么

| 测试类 | 内容 |
|---|---|
| `ProductSmokeTests` | 产品能启动、注册正常、两个 jar 互斥、必跑用例都在 |
| `MixinApplicationTests` | 本模组的每个 mixin 都真的注入到了目标类（客户端 mixin 测试服测不了，记为 `CLIENT_ONLY`） |
| `NacStructureTests` | 自动搭主机和组装矩阵：成形、连接；拆掉关键方块后失形、断开；补回后恢复 |
| `NacProcessingTests` | 加工和供电：有限能源仓缺电时等待、电网供电、能源仓装不下整批时拆批或逐 tick 运行、开工前和加工中输出堵塞（不丢产物、不重复交付） |
| `NacCalibrationTests` / `NacCalibrationTierTests` | 校准记账（白名单、合批、多族混合）和三档阈值下的实际功率、时长、扣电 |
| `NacPersistenceTests` | 批次运行中保存、从 NBT 重建，进度、校准、电网余额都不丢、不重复 |
| `NacRestartTests` | 保存后重建主机和模块，放料后能在时限内开工并交付（「重进才开工」那个问题的回归测试） |
| `PatternAssemblyTests`（仅完整版） | 惰性、MV 熔融、超级样板总成：不同样板来回推料不串配方、按编程电路区分配方、不接受别的配方表的配方 |
| `IndependentOwnershipTests`（仅完整版） | 其他机器独立线程：复制、剪切、放置回滚时不会复制出批次 |
| `RecipeConflictTests` | 扫描所有 GT 配方，找出同一配方表里一张样板的料能被另一条配方吃掉的情况；涉及本模组配方的新冲突会失败 |
| `ResourceIntegrityTests` | 本模组所有方块和物品的中英文名称、模型、贴图齐全 |

测试用的配方、物品和脚本在 `src/gametest/`，不会打进发行 jar。

## 已知问题（XFAIL 的 5 项）

| 编号 | 问题 |
|---|---|
| `NAC_ASSEMBLER_INPUT_COLLISION` | 本模组几条组装机配方的输入互相包含（例如真空输入仓和网格接口机械方块）。普通 ME 样板仓可能选错配方；猪咪样板总成有身份闸，不会串 |
| `NAC_ASSEMBLY_LINE_INPUT_COLLISION` | NAC 主机和各模块的装配线配方输入互相包含。同上 |
| `UHV_FREEZER_INPUT_COLLISION` | `superconductor_uhv_base_vf` 和上游的 UHV 超导锭冷却配方产物相同、输入是子集，样板总成也拦不住 |
| `NAC_CC_MISSING_REFERENCE_NAME` | 测试服没有整合包的 KubeJS 物品，部分 CC 的名字显示成「封装 空气」。整合包里不会出现；代码里 `NanochipCircuitComponents.Entry.realName()` 只判断了 null、没判断 AIR，可以顺手修 |
| `NAC_CC_PACK_TEXTURES` | CC 模型引用的 `kubejs:item/…` 贴图在测试服里没有。整合包里有 |

## 测不到的

- **客户端画面**：Jade、机器界面、CTM 连片渲染。测试服不开客户端，这些要进游戏看。
- **和 Enhancedcore 的 mixin 冲突**：完整版测试服装了 Enhancedcore，但它的 mixin 是 Java 21 字节码，开发环境的 Mixin 只支持到 Java 17，会把它们跳过（`debug.log` 里有 `Class version 65 required is higher than the class version supported`）。所以改了注入 gtlcore 的 mixin，一定要在真实整合包里启动一次。
- **整合包的 KubeJS 内容**：测试服是最小环境，没有整合包的物品、贴图、配方类型。
- **AE 合成 CPU 下单的完整流程**：样板总成用例直接调用推料接口，不经过 AE 合成 CPU。
- **其他机器独立线程的加工行为**：只测了复制/剪切，没测加工、扣电。这个功能默认关闭。

## 加一个测试

1. 照着同类的测试改。比如加工类的用例在 `NacProcessingTests`，它用 `fixture/` 里的工具搭结构、放料、供电，再逐 tick 检查。
2. 新的测试类要在 `GameTestMod.registerTests()` 里登记。
3. 测试专用的配方和物品放在 `src/gametest/` 的 KubeJS 脚本和数据包里，ID 用 `gtl_gametest:`，不要写进生产代码。
4. 断言要查真实的结果：物品数量、流体量、能源仓余量、电网余额。不要只看机器状态。
