# 2026-11-21 三件配方改动（0.3.478）

## 一、配方兼容大型化学反应釜（`ChemicalReactorMirror`）

**现象**：只写了 `gtceu:chemical_reactor` 的配方，单方块能跑、大型化学反应釜做不出来。
GTCEu 1.4.4 的大化反跑独立配方类型 `gtceu:large_chemical_reactor`，**不继承**单方块表。

**做法**：新增 `com.gtlmodular.common.data.chemical.ChemicalReactorMirror`，在
`ServerStartedEvent`（配方管理器就绪）把 `byType[chemical_reactor]` 的配方全量复制到
`byType[large_chemical_reactor]`：

- 复制用 `new GTRecipeBuilder(src, src.getType())` + `target.copyFrom(builder)`，输入/输出/概率/条件/NBT 原样带走；
- 新 id：`gtlmodular:large_chemical_reactor/lcr_mirror/<源 id> `；
- **两处一起写**：目标表 `lookup`（机器）+ `RecipeManager.byType`（JEI/样板识别）；
- 去重：目标表里已有**相同产物集合**的配方（手写 `_large.json`、KubeJS `gtr.large_chemical_reactor`、GT 自带大化反）⇒ 跳过；
- 尺寸检查：超过大化反 `maxIOSize(3,3,5,4)` 的跳过（不塞跑不了的配方）；
- 只追加、不清表；每条 try/catch，失败只记日志，不影响启动。

日志关键字：`大型化学反应釜兼容镜像结果`。

> 注意：与仓库里其它运行期注入（SpaceOreRecipeMirror / 3D 打印 / 获取配方）同一套时机，
> 只挂 `ServerStartedEvent`。执行 `/reload` 会重建配方管理器、镜像条目消失，
> **重启服务器/存档后自动恢复**。

## 二、3D 工具配方合并（单方块 / 多方块共用一张表）

**此前**：`disposable_tool_printing`（模具+1~6 号电路，多方块用）与
`disposable_tool_printing_basic`（模具+流体，单方块用）两张表 —— 2026-10-31 因为
「单方块调编程电路后输出槽冒出编程电路」拆出来的，结果同一把工具在 JEI 里出现两份。

**现在**：只保留 `gtlmodular:disposable_tool_printing` 一张表，
**LV/MV 单方块打印机与 3D 打印阵列共用**，配方统一为「一次性模具（不消耗）+ 72mB 流体 → 脆弱工具」，
不再带编程电路（材料本来就由流体区分）。`setMaxIOSize` 收回 `(1,1,1,0)`。

改动文件：`DisposableToolPrintTypes` / `DisposableToolPrintRecipes` / `DisposableToolPrintMachines`，
两份 lang 删掉 `gtlmodular.disposable_tool_printing_basic`。

## 三、力场压模零件工厂配方迁入模组

**此前**：112 条 `gtlmodular:component_parts/gte_cf_*` 全在整合包 KubeJS
（`kubejs/server_scripts/gte_component_assembly.js`，`// priority: 95`），模组里只有机器的获取配方
（装配线 + 研究门）。配方随 KubeJS 脚本的存亡而存亡。

**现在**：112 条全部生成为模组数据包
`src/main/resources/data/gtlmodular/recipes/component_parts/*.json`
（id 不变：`gtlmodular:component_parts/<行 id>`；duration 800 / EUt `VA[UV]=491520`），
生成器 `scripts/gen_component_parts_recipes.py` 可复跑。

**整合包侧建议同步删除**（部署 0.3.478 之后）：
- 删除 `kubejs/server_scripts/gte_component_assembly.js`（或改名 `.disabled`）
- 从 `kubejs/server_scripts/gtceu.js` 的 `run([...])` 列表里去掉 `"gte_component_assembly"`

不删也不会报错：同一 id 会先由数据包注册、随后被 KubeJS 的同内容版本覆盖，
功能一致，只是多一层重复来源。
