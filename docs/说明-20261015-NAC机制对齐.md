## 二、模块化：两个新类

- `NanochipAssemblyMatrixTier`（284 行）：档位解析 / 同级闸 / 折扣 / 配方档集中一处；**几何不复制**——装配格表在 `NanochipComplexPattern` 登记一次，判定复用生产同款 `elementOffset(...)`。
- `NanochipModuleImpurity`（63 行）：含杂度三条规则（满闸 / 排空判据 / 输出仓判据）。
- 两个大文件（`NanochipModuleMachine` 690 行、`NanochipComplexPattern` 1621 行）只各加 hook。

## 三、连带修掉的三处「测试自己咬自己」

1. **夹具不再硬编码机器功率**：`NacCalibrationFixture` 原写死 `2_097_152`/容量，换能源仓（模块不再受理激光仓后只能换能源仓）必炸；改成从 `module.getOverclockVoltage()` / `getEnergyContainer()` 读，判据变成「仓能不能预存最长探测批次」。
2. **测试配方件数收敛成单一口径**：KubeJS 的 `startup_scripts/nac_calibration.js`（注册输入物品）与 `server_scripts/nac_calibration_tiers.js`（生成配方）原本各有一份件数清单，改阈值时漏改一处 ⇒ 配方解析失败 ⇒ 夹具查不到配方**把整台测试服搞崩**。现在件数只在 startup 定义（`global.NAC_TIER_AMOUNTS`），server 复用，缺了直接抛错。
3. **无元数据配方的档位兜底改为 NH 默认 1**（不是按配方电压档），否则第三方/测试配方会被 20 格外壳档门槛卡掉。开关在 `NanochipAssemblyMatrixTier.FALLBACK_BY_RECIPE_VOLTAGE`。
