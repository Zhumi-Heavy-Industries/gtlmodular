# 说明：NAC 建造配方身份化（2026-10-16 · 与批次 2 同分支）

> 给同事看的变更说明。分支 `feature/nac-nh-mechanics`。
> **临时文件**：合并 `main` 前删；长期结论进 `CHANGELOG.md`。

## 一、为什么做

玩家反馈「NAC 配方有相同的」。冲突报告（`build/reports/gameTest/gtlmodular-recipe-conflicts.json`）我们命名空间 **114 条**，其中 **106 条是 `gtceu:assembly_line` 建造配方**：25 条建造配方都用同一套「机壳 + `gtceu:circuits/*` + 线圈 + SMD + 焊料」，编程电路全是 `circuit: -1` ⇒ 扫描器判据（同配方类型 + 同电路 + A 的原料能被 B 的供料满足）下**互相可满足**，样板会认错。

设计参照 GTL-Enhancedcore 的巨构配方：**配方 = 身份**——它 42 条配方每条都有 2~4 个「只在这一条出现」的功能件；电路只留给「同一台机器多条配方」。

## 二、做了什么

1. **新增 16 个核心件**：`nanochip_module_core`（骨架）+ 15 个 `nanochip_core_<模块>`（1 主机 + 14 模块）。含贴图（16×16，芯片底盘 + 族色复用 `NanochipCalibration.Family.color()`）、模型、lang（只新增键）。来源链：
   **骨架**（组装机 UV）→ **专属核心**（电路组装机，或主题机器：切割机 / 卷板机 / 化学浸洗槽 / 激光蚀刻机 / 真空冷冻机 / 拉丝机 / 发酵机）→ **模块 / 主机**（装配线）。
2. **15 台机器**：在原有线圈等原料**之外追加**各自专属核心件（**材料成本不变**，只加一件「身份证」）。
3. **11 件外壳 / 传送仓 / 真空管 / 样板工具**：各加一件互不重复的专属功能件（IV 档机器）并换一种主材料或流体。其中两处是**连带修**（不加就会红）：`nanochip_computational_matrix_casing` +`iv_polarizer`（否则被新核心配方 `nac_core_module_core` 的供料满足）、`naquadah_alloy_sheetmetal` +`iv_alloy_smelter`（否则撞 `gtmthings:assembler/wireless_energy_receive_cover_zpm`）。
4. **两条 `_eco` 备用路线**改用 **30 / 31 号编程电路**（真实写法 `{"content":{"type":"gtceu:circuit","configuration":N},"chance":0}`；`gtceu:programmed_circuit` 在本包不存在）。**旧样板需重新编码。**
5. `KnownRecipeConflicts` 摘掉 `NAC_ASSEMBLY_LINE_INPUT_COLLISION` / `NAC_ASSEMBLER_INPUT_COLLISION` 两条 XFAIL（问题已修；对应用例由 XFAIL 变 XPASS，`gametest.gradle` 允许 PASS/XFAIL/XPASS）。
6. 平台侧三处硬规矩（不发现会红）：物品模型必须按**物品 id** 命名（`ResourceIntegrityTests` 按注册路径找）；物品要覆盖 `getName()`（否则资源巡查判「名称缺失」）；`gradle/nac-resources.gradle` 必须把新物品加进「本产物物品清单」，否则**独立版构建直接失败**。

## 四、顺带修掉一条「假红」用例（值得记进经验）

`nac_processing_local_capacity` 原来把最后的总扣电钉死成 `3328`。同一棵树的不同轮次实测到 **3200（余量 0）/ 3328 / 3456 / 3584**：差别全部来自 GTCEu 原版 `RecipeLogic` 的「断电回退 2 tick、补电后重付」（一次 = 2 tick × 64 EU/t = 128），而回退次数随**服务器每 tick 的工作量**漂移。

**空载二分（每次 stash 后自动恢复，工作无丢失）**：

| 树 | 该用例 |
|---|---|
| 批次 2 已提交 | PASS（3328） |
| 批次 2 + 焊料 | PASS |
| 批次 2 + 焊料 + 配方身份化（纯数据新增） | FAIL（3584） |

改法：判**不变量**——必须付清基础 3200，余量必须是**整次回退**（`% 128 == 0`）且 ≤ 6 次，不钉死具体次数；注释里附上以上实测值。**排查顺序**：先空载重跑（区分「负载造成的超时/漂移」与真故障），再按路径 stash 二分。
