## 1. 现状：已经做到的部分（别重做）

`RequesterMachine.createUIWidget()` 里的注释就是当初的对照表：

```
3，0   网络状态        LabelWidget（在线/离线）
3，10  网格            8 列 × 2 行双层格 = 144 × 74
3，85  翻页条
3，105 阻塞提示
150，10 数量/并发面板  （挂在主面板右侧，点格子弹出来）
```

准确常量（`RequesterMachine`）：

| 常量 | 值 | 说明 |
|---|---|---|
| `ROWS` | 2 | 每页行数（照抄输入总成的 2 行双层格） |
| `COLUMNS` | 8 | 每列 8 格 |
| `PAGE_SIZE` | 16 | `ROWS × COLUMNS` |
| `PAGES` | 4 | 4 页 |
| `SLOT_COUNT` | 64 | |
| `SLOT_SIZE` | 18 | 单格宽；上=配置 18、下=库存 18 |
| `SLOT_HEIGHT` | 36 | `SLOT_SIZE × 2` |
| `GUI_WIDTH` | 150 | `AEDualConfigWidget` 的 144 + 左右各 3 |
| `GUI_HEIGHT` | 122 | 状态 10 + 网格 74 + 翻页 19 + 提示 14 + 余量 |

`RequesterSlotGrid`：`COLUMN_PITCH = 18`、`ROW_PITCH = SLOT_HEIGHT + 2 = 38`，
所以 `width() = 8×18 = 144`、`height() = 2×38 − 2 = 74`。

已经有的能力：网络状态标签、双层格、翻页条、右侧可拖动数量面板（数量 / 并发两个 `TextFieldWidget`）、
JEI 幽灵拖拽（`IGhostIngredientTarget`）、格内状态字符（0/1/2/3/4）。

## 2. 参照实现：`gtceu:me_input_assembly`

注册在 gtlcore：`GTLMachines.ME_INPUT_ASSEMBLY`，实例类 **`MEDualInputHatchPartMachine`**
（`deps-src/gtlcore-1.2.3.2-fix4/org/gtlcore/gtlcore/common/machine/multiblock/part/MEDualInputHatchPartMachine.java`）。

它的界面只有两句：

```java
@Override
public ModularUI createUI(Player player) {
    return new ModularUI(176, 180, this, player).widget(new FancyMachineUIWidget(this, 176, 185));
}

@Override
public Widget createUIWidget() {
    WidgetGroup group = new WidgetGroup(new Position(0, 0));
    group.addWidget(new LabelWidget(3, 0,
            () -> this.isOnline ? "gtceu.gui.me_network.online" : "gtceu.gui.me_network.offline"));
    group.addWidget(new AEDualConfigWidget(3, 10, this.aeItemHandler, this.aeFluidHandler,
            this::setPage, this.page, true));
}
```

### 2.1 配套控件签名（全部从源码读出，包前缀 `org.gtlcore.gtlcore.client.gui.widget`）

`AEDualConfigWidget`（三个构造，最后一个才是全参）：

```java
public AEDualConfigWidget(int x, int y, ExportOnlyAEItemList aeItem, ExportOnlyAEFluidList aeFluid,
                          IntConsumer pageSetter, int page)                                   // amountEditing=false, rows=2
public AEDualConfigWidget(..., int page, boolean amountEditingEnabled)                         // rows=2
public AEDualConfigWidget(..., int page, boolean amountEditingEnabled, int rows)
// 尺寸：super(new Position(x, y), new Size(144, max(1, rows) * 38 + 17))
//       rows=2 ⇒ 144 × 93；导航条相对 y = rows*38 + 1 = 77
// 对外方法：
public void enableAmount(int index);      // 弹出数量设置控件并定位到该格
public void disableAmount();              // 收起
public boolean isAmountEditingEnabled();
public int getSlotIndex(int visibleIndex);
```

`AEDualAmountSetWidget`（就是「点格子后弹出的那个数量框」）：

```java
public AEDualAmountSetWidget(int x, int y, AEDualConfigWidget parentWidget);
public void setSlotIndex(int index);
public TextFieldWidget getAmountText();
```

`IShiftAmountOperations`：

```java
public interface IShiftAmountOperations {
   void gtlcore$enableShiftAmountOperations();
}
```

`IExtendedClickData`：同目录，配合 Shift/右键的扩展点击语义。

> ⚠ **不能直接复用 `AEDualConfigWidget`**：它要求 `ExportOnlyAEItemList` / `ExportOnlyAEFluidList`
> （AE2 的只写输出列表），而请求器的数据模型是自建的 `RequesterSlots`。
> 所以能做的是**照它的交互模式自绘**，不是把它塞进来。

## 3. 逐项差距与改法

### A · 外框：补 `createUI` + `FancyMachineUIWidget`

- 现状：只重写 `createUIWidget()`，没有 `createUI()` ⇒ 少了 GTCEu 的标准外框（标题栏 / 侧边按钮）
- 改法：照参考机加

```java
@Override
public ModularUI createUI(Player player) {
    return new ModularUI(176, 180, this, player).widget(new FancyMachineUIWidget(this, 176, 185));
}
```

- 同时把 `GUI_WIDTH / GUI_HEIGHT` 往 176×180 体系靠（`createUIWidget()` 返回的 `WidgetGroup`
  尺寸要和外框协调，参考机这里是 `new WidgetGroup(new Position(0,0))` 不显式给尺寸）
- 风险：低。纯外观，不动数据
- 验收：窗口和别的 GT 机器长得一样，网格仍居中

### B · 数量交互：拖动面板 → 点格子弹窗 + Shift 步进

- 现状：`RequesterAmountBox`（9.2 KB）是「右侧浮出、标题栏可拖动、两个 `TextFieldWidget`（数量/并发）」
- 目标：照 `AEDualConfigWidget.enableAmount(index)` 的模式 —— **点格子 → 该格的数量框出现在格边**，
  再点别处/关闭 → `disableAmount()`；并接 Shift 步进（`IShiftAmountOperations` 语义）
- 改动文件：
  - `RequesterAmountBox.java` —— 从「常驻可拖动面板」改成「跟随选中格的弹层」
  - `RequesterSlotWidget.java` —— `mouseClicked` 的 `ACTION_SELECT(4)` 分支改为调用 `enableAmount(index)`
  - `RequesterSlotGrid.java` —— 承担 `enableAmount/disableAmount/选中索引` 的三个方法（对齐参考控件的 API 形态）
- **硬约束（最重要）**：
  - `RequesterSlots` 的**存档格式与同步字段不能变**（含 NBT codec、`UPDATE_SLOT=100` 的 action 协议）
  - `RequesterOrderEngine` 读取的 `target`（目标数量）/ `batch`（并发）**语义不能变**——
    这是下单引擎的唯一输入，改错会导致自动下单行为变化
- 风险：**中高**。这不是纯视觉，属于「换交互协议」，建议单独一个提交、单独一条分支
- 验收：改完 `target/batch` 的落盘值与旧版一致（可写脚本比对 NBT）

### C · 格内数字走 `TextFormattingUtil`

- 现状：`RequesterNumbers.display(long)` / `displayFluid(int)` 自己实现紧凑格式（`1.83M`）
- 目标：格内文字用 LDLib 的 `TextFormattingUtil`（文档 §8.4 早就写了这条待办）
- 改动文件：`RequesterSlotWidget.drawKey(...)` + `RequesterNumbers`
- 风险：低。注意别把 `RequesterNumbers.parse(String)` 的解析口径一起改掉（输入解析仍要能吃 `1.83M`）

## 4. 红线（踩了会出事故）

1. **方块 id 不能改**：`gtlmodular:me_requester`（`docs/ME库存补充仓_技术细节.md` §7.1）
2. **一个配方只能有一个来源**：请求器获取配方是纯数据包 `data/gtlmodular/recipes/me_requester.json`，
   代码里不要再注册一遍（否则 JEI 并列两页，见 `5b36b31` 的恒星炉事故）
3. **不动 `RequesterOrderEngine`**：本次是 UI 任务，引擎逻辑一行都不要改
4. **存档兼容**：`RequesterSlots` 的结构体字段只许加不许删、不许改类型
5. **版本号 +1**：`build.gradle:12`
