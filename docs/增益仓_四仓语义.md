# 增益仓 · 四仓语义（对齐 GTO 官方）

> 来源：GTO（GregTech Odyssey / GTOCore）游戏内「增益仓」任务章节原文，及 GTO/GTET 源码。
> 本文是**口径基准**：以后实现/修改任一增益仓，先对照这里，避免数值与语义跑偏。

## 什么是增益仓

贴在多方块外壳上的部件仓，用于**提高机器效率**。GTO 共定义了四种：

| 仓 | 适用范围 | 一句话作用 |
|---|---|---|
| **加速仓** | 大部分机器 | **无条件**加快机器速度（按百分比缩短配方时间） |
| **并行控制仓** | 可并行机器 | 一次性翻倍功率处理多个配方（≈ 无损超频） |
| **线程仓** | 仅跨配方并行机器 | 尽量同时跑多个**不同配方**填满并行 |
| **超频仓** | 几乎只有巨构 | 直接改超频的时间倍率（UK 即无损，更高越超越省电） |

另有「可配置维护仓」可提供**微弱的机器加速**效果（非四仓之一）。

---

## 1. 加速仓（Accelerate Hatch）

- **适用**：大部分机器。
- **作用**：**无条件**加快机器运行速度。
- **数值**：数字表示「加速仓等级 **高于** 配方等级时，配方时间 × 该百分比」。
- **惩罚**：加速仓等级每**低于**配方一级，加速效果**减少 20%**。
- **实现口径**（GTO `AccelerateHatchPartMachine`）：
  ```
  reduction = 玩家设定百分比        // 范围 [min, 100]
  t = 配方tier - 加速仓tier
  if (t > 0) reduction = min(100, reduction + 20 * t)   // 每低一级 +20%（加速变弱）
  duration = max(1, duration * reduction / 100)
  ```
- **档位范围**：GTO 原版 UV~MAX 7 档，`min = 52 - 2*tier`（LV=50% → MAX=24%）。
  本模组按需扩展到 **LV(1) ~ MAX(14) 共 14 档**，同公式。
- **关键性质**：**不看超频档数、不受电压墙限制**，只要仓等级 ≥ 配方等级就有效。
  因此与**批处理叠加是纯增益**：批处理放大每批数量（`modifyDuration=false`，时长不变），
  加速仓压缩批次绝对时长 → 吞吐 = N / (T × ratio)。

## 2. 并行控制仓（Parallel Control Hatch）

- **适用**：可并行机器。
- **作用**：允许机器一次性以**翻倍功率**处理多个配方，某种意义上相当于**无损超频**。
- **对应 GTCEu**：`PartAbility.PARALLEL_HATCH`（`IParallelHatch`）。

## 3. 线程仓（Thread Hatch）

- **适用**：**仅**跨配方并行机器。
- **作用**：允许机器尽量**同时**多运行几个**不同配方**，以跑满并行、提高效率。
- **本模组实现**：`ThreadHatchPartMachine` / `IThreadHatchPart`，7 档（UV~MAX），
  线程数上限 `1 << (tier - LuV)`，配合独立线程引擎 `ThreadedRecipeLogic`。

## 4. 超频仓（Overclock Hatch）

- **适用**：**几乎只有巨构**可以用。
- **作用**：非常强大，**直接修改机器超频的时间倍率**。
- **关键数值**：
  - UV 级别 = 一般的有损超频；
  - **UEV 级别即可达到无损超频**；
  - **UEV 以上越超越省电**；
  - （UEV 以上机器会**优先计算超频，再计算并行**。）
- **与 GTET 的差异（重要）**：GTO 官方口径是「时间倍率」，GTET（`ETOverclockHatches`）用的是
  `E×S` 的「速度/能效」双参数模型 —— **两者不一致**。本模组若做超频仓，应以 GTO 口径为准。

| 超频仓 | 已实现（按 GTO 时间倍率） | **增强版核心的机器** | `OverclockHatchPartMachine`；生效 `OverclockHatchLogic` |

### 加速仓为什么有三条生效链路

原生存口是 `IMultiPart#modifyRecipe`，只从 `doModifyRecipe` 被调用。按字节码核实，
下面两类配方逻辑从不调它，装上仓会「成形但不加速」，因此各自补了一针：

| 配方逻辑 | 谁在用 | 生效方式 |
|---|---|---|
| gtceu 原生 `RecipeLogic` | 大部分机器 | `doModifyRecipe → modifyRecipe`（原有） |
| gtlcore `MultipleRecipesLogic` | GTL 核心的巨构、终端、NAC 主机 | `findAndHandleRecipe` 尾部注入 |
| 增强版私有 `MultipleRecipesLogic` | 黑物质分解机 | 同上 |

三条链路共用 `AccelerateHatchPartMachine#applyTo` 一份公式，不会出现两种口径。
注入点刻意避开 `checkRecipe` —— 它是配方查找的过滤器，每条配方会被回调多次。

### 线程仓 / 超频仓（只覆盖增强版核心的机器）

- **线程仓**：只做结构放行，装上去可成形。多线程仍需本模组线程引擎接管，
  增强版的机器尚未接入，所以目前是「装得上、不增加并行」。
- **超频仓**：在 `doModifyRecipe` 返回前，按仓倍率与默认倍率之比换算配方耗时，
  等价于用仓的倍率重新超频。已实现 `ISpeedEnergyOverclockable` 的机器会被跳过，
  不与 `OverclockProfiles` 重复叠加。

两个开关（`config/gtlmodular-common.toml`）：`accelerateHatch.anyMultiblock`、
`extendHatches.enabled`，均默认开。

### 加速仓的安装范围（除增强版以外）

口径是「除增强版核心（GTL-Extend）接管的机器以外的所有多方块」：

- 放行：gtceu 原生、gtlcore、第三方附属，以及本模组自己声明过加速仓的结构；
- 不放行：`ExtendHatchPredicate` 名单里的增强版机器。这些机器只接受线程仓 / 超频仓；
- 结构侧排除只看构建期凭据，**不影响旧存档**：已经摆在增强版机器上的加速仓照旧生效
  （生效侧只读 `accelerateHatch.anyMultiblock`，不看结构排除）。
