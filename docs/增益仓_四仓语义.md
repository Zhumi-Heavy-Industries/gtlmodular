# 增益仓 · 四仓语义（对齐 GTO 官方）

> 来源：GTO（GregTech Odyssey / GTOCore）游戏内「增益仓」任务章节原文，及 GTO/GTET 源码。
> 本文是**口径基准**：以后实现/修改任一增益仓，先对照这里，避免数值与语义跑偏。

## 什么是增益仓

贴在多方块外壳上的部件仓，用于**提高机器效率**。GTO 共定义了四种：

| 仓 | 适用范围 | 一句话作用 |
|---|---|---|
| **加速仓** | 大部分机器 | **无条件**加快机器速度（按百分比缩短配方时间） |
| **并行控制仓** | 可并行机器 | 一次性翻倍功率处理多个配方（≈ 无损超频） |
| **线程仓** | 仅跨配方并行机器 | 尽量同时跑多个**不同配方**填满并行 |
| **超频仓** | 几乎只有巨构 | 直接改超频的时间倍率（UK 即无损，更高越超越省电） |

另有「可配置维护仓」可提供**微弱的机器加速**效果（非四仓之一）。

---

## 1. 加速仓（Accelerate Hatch）

- **适用**：大部分机器。
- **作用**：**无条件**加快机器运行速度。
- **数值**：数字表示「加速仓等级 **高于** 配方等级时，配方时间 × 该百分比」。
- **惩罚**：加速仓等级每**低于**配方一级，加速效果**减少 20%**。
- **实现口径**（GTO `AccelerateHatchPartMachine`）：
  ```
  reduction = 玩家设定百分比        // 范围 [min, 100]
  t = 配方tier - 加速仓tier
  if (t > 0) reduction = min(100, reduction + 20 * t)   // 每低一级 +20%（加速变弱）
  duration = max(1, duration * reduction / 100)
  ```
- **档位范围**：GTO 原版 UV~MAX 7 档，`min = 52 - 2*tier`（LV=50% → MAX=24%）。
  本模组按需扩展到 **LV(1) ~ MAX(14) 共 14 档**，同公式。
- **关键性质**：**不看超频档数、不受电压墙限制**，只要仓等级 ≥ 配方等级就有效。
  因此与**批处理叠加是纯增益**：批处理放大每批数量（`modifyDuration=false`，时长不变），
  加速仓压缩批次绝对时长 → 吞吐 = N / (T × ratio)。

## 2. 并行控制仓（Parallel Control Hatch）

- **适用**：可并行机器。
- **作用**：允许机器一次性以**翻倍功率**处理多个配方，某种意义上相当于**无损超频**。
- **对应 GTCEu**：`PartAbility.PARALLEL_HATCH`（`IParallelHatch`）。

## 3. 线程仓（Thread Hatch）

- **适用**：**仅**跨配方并行机器。
- **作用**：允许机器尽量**同时**多运行几个**不同配方**，以跑满并行、提高效率。
- **本模组实现**：`ThreadHatchPartMachine` / `IThreadHatchPart`，7 档（UV~MAX），
  线程数上限 `1 << (tier - LuV)`，配合独立线程引擎 `ThreadedRecipeLogic`。

## 4. 超频仓（Overclock Hatch）

- **适用**：**几乎只有巨构**可以用。
- **作用**：非常强大，**直接修改机器超频的时间倍率**。
- **关键数值**：
  - UV 级别 = 一般的有损超频；
  - **UEV 级别即可达到无损超频**；
  - **UEV 以上越超越省电**；
  - （UEV 以上机器会**优先计算超频，再计算并行**。）
- **与 GTET 的差异（重要）**：GTO 官方口径是「时间倍率」，GTET（`ETOverclockHatches`）用的是
  `E×S` 的「速度/能效」双参数模型 —— **两者不一致**。本模组若做超频仓，应以 GTO 口径为准。
