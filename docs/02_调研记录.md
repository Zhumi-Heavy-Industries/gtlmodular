## 3. 机制参数（官方 tooltip 原文要点）
- EBF（gtlcore 覆写）：耗时倍数 = max(配方温度/炉温, 0.5)；每超配方温度 900K → 耗能 ×95%（不计超频）；每超 1800K → 一次超频 100% 效率（无损超频）；>MV 每级电压 +100K。
- 宏原子剥离器：星辉(Starmetal)+ 线圈起用；每高出 1200K → 并行 +300；星规矩阵 ≤256，并行倍率 = 2^(6+10·((n-1)/184)²)；跨配方并行、∞并行。

## 5. 机器注册生命周期（GTM 1.4.4，经字节码核实 + 实机验证）
- `gtceu:machine`（GTRegistry）创建即冻结；GTM 在 `GTMachines.init()`（gtceu `CommonProxy.init` 的构造末尾延迟队列内）执行：
  `MACHINES.unfreeze → KubeJS钩子 → ModLoader.postEvent(new GTCEuAPI.RegisterEvent<>(MACHINES, MachineDefinition.class)) → MACHINES.freeze()`。
- **机器只能在该 RegisterEvent 窗口内注册**（其后即冻结）：不要用 `IGTAddon.initializeAddon`（该回调晚于窗口，MACHINES 已冻结，会抛 `[register] registry gtceu:machine has been frozen`），更不要在 @Mod 构造里直接注册（当时 `gtceu:compass_section` 已冻结，抛 ExceptionInInitializerError）。
- gtlcore 做法（本模组 M1 已照搬并实机验证）：@Mod 构造中对 **mod 事件总线** `addGenericListener(MachineDefinition.class, 具体事件类型方法引用)`；方法参数必须写成具体事件类 `GTCEuAPI.RegisterEvent<ResourceLocation, MachineDefinition>`（写成 `IGenericEvent` lambda 会选中按基类 GenericEvent 挂载的重载，mod 总线校验 `IModBusEvent` 失败抛 IllegalArgumentException）。
- 创造标签页/可见性：本模组自建 `REGISTRATE.defaultCreativeTab(name, builder→{builder.displayItems(new GTCreativeModeTabs.RegistrateDisplayItemsGenerator(modid, REGISTRATE)); …}).register()`，并**随后必须** `REGISTRATE.creativeModeTab(() -> 该标签页entry)`——GTM 显示生成器只收录 `GTRegistrate.isInCreativeTab`（TAB_LOOKUP）为真的条目，而 TAB_LOOKUP 只在注册条目前把该标签页设为 currentTab 时才填充；漏掉这步会出现“机器能跑、配方在、任务能给，但创造/JEI 找不到物品”。
- 参考证据：gtlcore `CommonProxy`（构造里 `REGISTRATE.registerEventListeners` + `addGenericListener(MachineDefinition.class, registerMachines)`；`registerMachines` 回调里调 `GTLMachines.init()`）、`GTLRegistration`（`REGISTRATE.defaultCreativeTab((ResourceKey)null)`）、`GTLCreativeModeTabs`（defaultCreativeTab + RegistrateDisplayItemsGenerator）。
