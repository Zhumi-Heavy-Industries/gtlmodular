# 说明：优化组织器净化水模型对齐 NH（2026-10-17）

> 给同事看的变更说明。分支 `feature/nac-nh-mechanics`。
> **临时文件**：合并 `main` 前删；长期结论进 `CHANGELOG.md`。

## 一、按船长口径改了什么

四台优化组织器（光学、奇异、寰宇、超因果）的净化水模型从「取最高一级 + 连续加成 + 固定 100 mB/s + 各级都算」改成 NH 的规则：

| 项 | 新口径 |
|---|---|
| 进料 | **必须同时提供两种净化水**，且两种**必须属于不同效果类别**（水耗 / 配方耗时 / EU/t） |
| 等级 | **保留 1~16 级**，每 3 级映射 NH 一档：1–3 三级、4–6 四级、7–9 五级、10–12 六级、13–15 七级、16 八级 |
| 效果 | 水耗 ×0.8 / ×0.6、配方耗时 ×0.9 / ×0.7、EU/t ×0.9 / ×0.7（同一类别内累乘） |
| 基础消耗 | 1000 / 800 / 800 / 600 / 600 / 400 mB/s（开工时每种水必须达到自己的基础量） |
| 运行扣水 | **每 20 tick** 按两种水的水耗倍率累乘扣除，**向上取整为整数 mB** |
| 缺料 | **缺少任一种水 ⇒ 停机**（与缺电同级） |
| 满校准 | 三级光学校准时，每种水的增益**再应用一次**（对应倍率平方） |

## 二、怎么实现的（可维护性）

新增 `NanochipPurifiedWater`（纯逻辑、无机器依赖）：

- 档位表用**百分数整数**保存，扣水与平方全用整数分数（`分子/分母`）累乘，**没有浮点误差**，向上取整只有唯一答案；
- 选择是**确定性**的：按类别聚成一条（档位取该类最高一级、量按该类所有等级合计）→ 再取等级最高的两类，与流体扫描顺序无关；
- 扣水计划**跨整个类别取水**（同一类别可能跨两个档，例如水耗类的三级+四级），不会出现「判定够水却抽不满」。

## 三、修掉的一个真问题

实现初稿按**档位**聚合（`stocksOf`），而水耗类有三级/四级两档 ⇒ **只喂 1~6 级的玩家会选出两份水耗类水**，违反「必须不同类别」。已改成按类别聚合，并补了用例覆盖（`oneCategoryIsNotEnough`）。

**这个问题的来源值得记**：档位表和类别是两张正交的表，凡是「按档位分组」的地方都要问一句「同一类别会不会被分成两条」。

## 五、老存档注意（已进 CHANGELOG）

只喂一种净化水、或两种水同属一个效果类别的存量组织器，升级后会停机；补另一种类别的净化水（例如水耗类 + 耗时类各一种）即恢复。界面已改成显示「耗时倍率 / 耗电倍率 + 是否供足」，不再显示旧的连续 strength。
