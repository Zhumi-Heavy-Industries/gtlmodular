# 一次性工具 3D 打印机 · 设计与实现（0.3.211）

> 来源：GTO（gtocore）3D 打印机里「3D打印：一次性工具」那一个分支。
> 队长口径：单独剥离成 **2 台单方块（LV/MV）+ 2 台多方块（8 线程阵列 / 线圈巨构）**；
> 配方直接套 GTO，模具配方直接套，产物换成包里的**脆弱工具系列**；
> 机制**不依赖 gtlcore / gtladditions**，用本模组自己的独立线程引擎。

---

## 1. GTO 原逻辑（反编译取证）

`com.gtocore.data.recipe.generated.GTODisposableToolHandler`：

```java
// 对每个「有 TOOL 属性 + 有流体」的材料，每种工具一条：
GTORecipeTypes.THREE_DIMENSIONAL_PRINTER_RECIPES.recipeBuilder(...)
    .notConsumable(tool.mold)                       // 一次性模具，不消耗
    .inputFluids(material.getFluid(72))             // 72mB 材料流体
    .outputItems(tool.item, durability / tool.consume)
    .EUt(30).duration((int) material.getMass());
```

- 8 种工具与 consume：file 4 / wrench 8 / crowbar 3 / wire_cutter 9 / hammer 6 / mallet 6 / screwdriver 4 / saw 4。
- 模具来源（`com.gtocore.data.recipe.classified.FluidSolidfication`）：

```java
FLUID_SOLIDIFICATION_RECIPES.builder(...)
    .inputItems(toolTag)                 // 一把对应工具（消费）
    .inputFluids(GTMaterials.Steel.getFluid(576))
    .outputItems(disposableMold)
    .EUt(30).duration(800);
```

### 2.1 为什么产物不是 GTO 的 disposable tool

队长明确「产物直接套用我们脆弱工具系列，那些东西在脆弱工具元件包里面都有」。
包里脆弱工具是 KubeJS 注册的普通物品（食物属性），不是 GT 工具，所以：
- 产物 id 固定 `fragile_tool:fragile_*`；
- 单条配方产量 = `材料耐久 / consume`，**封顶 64**（它们是 64 堆叠普通物品，不能出现超堆）；
- 产物不随材料变化（同一个脆弱工具物品），材料差异只体现在「消耗哪种流体」上。

### 2.2 机器

| id | 类 | 说明 |
|---|---|---|
| `lv_disposable_tool_printer` | `DisposableToolPrinterMachine extends SimpleTieredMachine` | tier 1；罐 16000mB |
| `mv_disposable_tool_printer` | 同上 | tier 2；GT 标准超频 |
| `disposable_tool_printing_array` | `DisposableToolPrinterMultiblockMachine extends WorkableElectricMultiblockMachine` | 7×5×7；8 线程 |
| `disposable_tool_printing_megastructure` | `DisposableToolPrinterMegastructureMachine extends CoilWorkableElectricMultiblockMachine` | 9×7×9；8 线程 + 温度并行 |

- 两小机器都用自绘机器脸 `gtlmodular:block/machines/disposable_tool_printer`（静态 + 6 帧动画）。
- 多方块用钛稳定机壳 + 钢化玻璃；巨构腰部两圈 `Predicates.heatingCoils()`。
- aisle 写法遵守 GTCEu 惯例：**第 1 个字符串 = 最底层，第 1 个 aisle = 背面，最后一个 aisle = 正面**。
- 结构里所有机壳格都可换 IO/能量/维护仓 + 标准并行仓（`PartAbility.PARALLEL_HATCH`，最多 1 个）。

### 2.3 独立线程引擎

`com.gtlmodular.common.machine.engine` 三个类（详见类内 javadoc）：

```text
ConcurrentRecipeEngine  纯 List<Batch>：
  ① 每条 tickInputs 成功才 progress++
  ② 涨满 → 先摘表 → finishOutputs（afterWorking/postWorking/出料）
  ③ 有空位 → findBatch → consumeInputs（原子扣料，一条只扣一次）→ 入表
ThreadedRecipeLogic     RecipeLogic 子类：
  findBatch = 配方修改器 → accurateParallel(并行仓 × 温度倍率) → matchRecipe/matchTickRecipe/条件
  展示回写：第 0 条批次的 progress/duration/lastRecipe → GUI/Jade 单进度条
IThreadedRecipeMachine  机器契约：baseThreads()=8 / parallelMultiplier()（普通 1、巨构 2^n）
```

- 并行仓：遍历已成形 `IMultiController.getParts()`，取最大 `IParallelHatch#getCurrentParallel()`。
- 巨构：`2^clamp((线圈温度-1800)/900, 0, 12)`，基准 1800K（第一档线圈），封顶 4096×。
- 失形/复位：覆写 `resetRecipeLogic` 清空批次表（基类不知道本类的批次表）。
- 每个 tick 在推进前调用一次 `machine.onWorking()`（部件级 upkeep，调 N 次会放大 N 倍）。
- **零 gtlcore / gtladditions import**（旧 NAC 引擎里的 `IGTRecipe#getRealParallels` 专门用于存档，
  本引擎不存该字段，并行份数已摊进配方 Content 数量）。

### 2.4 配方注入

照 `SpaceOreRecipeMirror` 的既有纪律，**不写数据包 JSON**、运行期在 `ServerStartedEvent` 生成：

1. 遍历 `GTCEuAPI.materialManager.getRegisteredMaterials()`：
   - 跳过 `NO_UNIFICATION`、无 TOOL、无流体、材料名为空；
   - 流体：中子素/安普洛 → `quantanium`（无流体时退回自身）；
   - 每种工具一条，id = `gtlmodular:disposable_tool_printing/<材料>_to_<工具>`（path 归一化）。
2. 10 条模具配方注入 `GTRecipeTypes.FLUID_SOLIDFICATION_RECIPES`（`forge:tools/<tag>` 消费 1 把工具）。
3. **两处登记**：`type.getLookup().addRecipe(...)`（机器找配方）+ `RecipeManager.byType`（JEI/样板识别），
   反射字段名 `f_44007_`（生产）/`recipes`（开发）。
4. 幂等：打印表先 `removeAllRecipes()` 再灌；固化表只补缺（绝不整表清空，避免清掉 GT 自己的配方）。
5. `/reload` 后运行期注入会丢；重新进世界/重启即可重建（与工程既有镜像一致）。
