GTL-Modular 源码交付包 —— 构建说明
=====================================

【一、需要什么】
  · JDK 21（验证过 Eclipse Adoptium 21.0.12；工程 options.release = 17）
  · Gradle 8.5（包内 gradlew / gradlew.bat 已有）

【二、包内容】
  1) gtlmodular-源码-交付版_<时间>.zip  = 源码（src / build.gradle / settings.gradle / gradle wrapper）
  2) gtl-modular-libs_<时间>.zip        = 全部依赖 jar（19 个，含新旧 gtlcore/gtladditions 备份）
  3) 本说明文件

【三、怎么搭起来】
  1. 解压源码包，得到 gtl-modular\ 目录
  2. 解压 libs 包，把里面的 libs\ 整个目录放到 gtl-modular\libs\（与 build.gradle 同级）
     注意：libs 里的 jar 是构建期依赖（flatDir + fileTree 通配），文件名不要改
  3. 构建：
       cd gtl-modular
       set JAVA_HOME=<你的 JDK21 路径>
       gradlew.bat build --offline --no-daemon --no-watch-fs --max-workers=1 --console=plain
     产物：build\libs\gtlmodular-0.3.132.jar
  4. 调试进游戏：
       gradlew.bat runClient --offline --no-daemon

【四、依赖版本（编译期必须一致）】
  · gtceu 1.20.1-1.4.4
  · gtlcore 1.2.3.2-fix4        （libs\_old_20261011-1501\ 另有 fix2 旧版）
  · gtladditions 3.3.1Custom_SubSpace（旧版 3.2.8-fix2 在 _old 目录）
  · ldlib 1.0.33.b / jade 11.13.3 / jei 15.49.0.188 / ae2 15.4.10 / registrate 1.3.3 / kubejs 2001.6.5 等
  · GTL-Enhancedcore 不在编译依赖内（运行期由整合包提供）

【五、注意事项（踩过的坑）】
  · 不要加 -x spotlessJavaCheck（本工程没有该 task，会直接构建失败）
  · 全部依赖走 libs\ 本地 jar（flatDir），不要改成 maven 远程坐标
  · JDK 必须是 21（用 17 会因 gtladditions 的 class 版本失败）
  · 若换用新版 gtlcore/gtladditions，请同时替换 libs\ 里的 jar，否则可能 NoSuchMethodError

【六、代码结构与定位】
  · 主体：src\main\java\com\gtlmodular\（108 个类）
     - common\machine\nanochip\   = 纳米芯片组装复合体（NAC）主机 / 14 类模块 / 线程 / 并行 / 校准
     - common\machine\            = 样板总成（猪咪 / 惰性）、样板仓归档
     - common\data\               = 机器与方块注册、图案、谓词
     - client\                    = Jade / JEI / CTM / 渲染
  · 入口：src\main\java\com\gtlmodular\GTLModular.java（@Mod 注解）
  · 关键常量：GTLModular.MOD_ID = "gtlmodular"（资源与注册命名空间也用它）
  · 资源：src\main\resources\assets\gtlmodular\（lang/贴图/模型）、data\gtlmodular\（配方/标签）
